# AlexTarget — лендинг

## О проекте
Рекламный одностраничный лендинг для бренда **AlexTarget**.

**Услуги:**
1. Настройка таргетированной рекламы в Instagram и Google
2. Внедрение ИИ в отдел продаж
3. Автоматизация бизнес-процессов через ИИ

**Аудитория:** предприниматели и владельцы бизнеса среднего уровня и выше, Казахстан.

**Цель сайта:** лидогенерация — посетитель оставляет заявку через форму, заявка приходит владельцу в Telegram.

**Язык:** только русский.

**Материалы:** готового брендинга (лого, цвета, фото, тексты) нет — всё создаётся с нуля в рамках проекта.

## Дизайн-направление
Эстетика фильма «Матрица»: тёмный фон, неон (зелёный/циан), цифровой дождь, глитч-эффекты. Обязательна 3D-анимация — не декоративный элемент, а центральная часть впечатления от сайта (в первую очередь в Hero-секции).

Важно про контраст: яркий неон — только для крупных заголовков/акцентов. Текст основного содержания — на более светлом нейтральном оттенке (не чистый неон), чтобы проходить WCAG AA по читаемости.

## Структура страницы (одна страница, скролл)
1. **Hero** — заголовок с УТП, подзаголовок, CTA-кнопка к форме, 3D/шейдерный фон
2. **О продукте / преимущества** — три карточки услуг (см. выше)
3. **Форма заявки**
4. **Контакты** — включая запасной канал связи (WhatsApp/Telegram-ссылка) на случай сбоя формы

## Технический стек
- **Vite + vanilla TypeScript** — сборка, без React/Next.js: страница одна, без роутинга и сложного состояния, фреймворк не нужен
- **Three.js** — 3D/шейдерные эффекты, императивный render-loop
- **Netlify** — хостинг статики + Netlify Functions (serverless) для релея заявок в Telegram
- **vite-plugin-glsl** (опционально) — импорт шейдеров как `.glsl`-файлов

## 3D / Matrix-эффект
Два слоя, оба через Three.js:
1. **Цифровой дождь** — полноэкранная плоскость с ortho-камерой, кастомный `ShaderMaterial`. Текстура символов генерируется один раз через offscreen `<canvas>`, анимация «падения» считается во фрагментном шейдере (GPU-bound, не зависит от количества «колонн» — важно для производительности).
2. **3D-акцент** — wireframe-объект (например, икосаэдр) с шумовой деформацией вершин + `UnrealBloomPass` для неонового свечения, лёгкий параллакс от курсора/наклона (мобильные).

**Обязательные фолбэки:**
- `prefers-reduced-motion: reduce` → статичный CSS-фон вместо WebGL (без анимации)
- Ошибка инициализации WebGL → тот же статичный CSS-фолбэк
- Понижение качества на мобильных: `devicePixelRatio` капается, `UnrealBloomPass` отключается, плотность «колонн» дождя снижается
- Рендер-луп ставится на паузу через `IntersectionObserver`, когда canvas вне вьюпорта
- Three.js подгружается через динамический `import()` после первой отрисовки — не блокирует LCP остального контента

## Форма заявки → Telegram
**Поля:**
- Имя * (текст)
- Контакт для связи * (телефон/WhatsApp/Telegram)
- Компания (текст, опционально)
- Интересующая услуга * (селект: три услуги + «Не уверен, нужна консультация»)
- Комментарий (textarea, опционально)
- Согласие на обработку персональных данных * (чекбокс + ссылка на короткую политику конфиденциальности на сайте)
- Honeypot-поле (скрытое, анти-спам, не показывается пользователю)

**Поток данных:**
1. Клиент → `POST /api/submit-lead` (JSON)
2. `netlify.toml` редиректит `/api/submit-lead` → `/.netlify/functions/submit-lead`
3. `netlify/functions/submit-lead.ts`:
   - валидирует payload на сервере (не доверяет только клиентской валидации)
   - проверяет honeypot — если заполнен, тихо возвращает 200 без отправки в Telegram
   - берёт `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` из переменных окружения Netlify (никогда не в клиентском коде, никогда не в git)
   - вызывает `https://api.telegram.org/bot<token>/sendMessage`
4. Клиент показывает успех/ошибку; при ошибке — не блокирует пользователя, есть запасной контакт (WhatsApp/Telegram-ссылка) в секции «Контакты»

**Создание бота:** через `@BotFather` в Telegram (`/newbot`) — токен и chat_id клиент предоставит перед подключением реальных credentials. До этого разработка и тесты идут на одноразовом тестовом боте.

## Прочее
- **Копирайт:** весь текст (заголовки, описания услуг) пишется с нуля под проект, без lorem ipsum, ревью с клиентом перед запуском
- **Соцдоказательства:** реальных кейсов/отзывов пока нет — не выдумывать, делать акцент на чётком описании услуг и процесса; отзывы добавить позже, когда появятся
- **Политика конфиденциальности:** короткий текст на сайте (не отдельная юридическая консультация) — под чекбоксом согласия в форме
- **Домен:** пока нет — деплой сначала на дефолтный поддомен Netlify, домен подключается позже без изменения архитектуры
- **Dev-окружение:** на машине пока не установлен Node.js — первый шаг реализации
